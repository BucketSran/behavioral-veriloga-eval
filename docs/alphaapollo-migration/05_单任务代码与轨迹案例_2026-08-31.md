# Case study：公开模拟成功，为什么最终还是 0 分？

日期：2026-08-31。审查基线 `87c10cb65e`；运行代码为 `8d782880c7`。
这是已有免费 smoke 的代码/证据复查，不是新模型实验，也没有修改运行代码。

## 先看结论

这个任务经历了：**空目录请求模拟 → 收到缺文件反馈 → 写入占位候选 →
公开模拟成功并返回波形 → 提交冻结 → 隐藏终评 `behavior_failure / 0.0`**。

它说明“文件已交齐”“工具运行成功”“任务功能正确”是三个不同判断。
测试通过，是因为 harness 正确走完并区分这些状态，不是因为候选答对。
候选由脚本预先安排，仅根据公开接口生成 stub；不能说模型学会了修复。

旧设施也并非只有提示词控制。它在 Docker 模式下已有隔离、读写挂载、No-EVAS 环境、
提交检查、轨迹和 trusted replay。新路径保留这些基础，主要把不同职责拆成
可共用、可验证的边界，并新增显式工具及更严格的事件/证据关联。

## 2. 四轮实际发生了什么？

下表的 seq 来自 `evidence/native-episode/trajectory.jsonl`，不是事后编写的
伪轨迹。C0/C1 是便于阅读的候选树哈希缩写，完整值见第 6 节。

| 模型轮次 / 事件序号 | 动作 | 实际反馈与状态 | 计量与候选 |
| --- | --- | --- | --- |
| 初始化 seq 0 | 创建 episode | 固定 condition、capability/profile、预算 | 候选 C0，为空树 |
| 第 1 轮 seq 1–5 | `vaevas_public_simulate({})` | `candidate_incomplete`；`done=false`；无 receipt；不执行 EVAS | 模型 1/4，公开请求 1/2，候选仍 C0 |
| 第 2 轮 seq 6–10 | Bash 写入公开接口 stub | `succeeded`；只是文件写入成功 | 模型 2/4，候选 C0→C1 |
| 第 3 轮 seq 11–15 | 再次 `vaevas_public_simulate({})` | `returncode=0`，waveform available，`done=false` | 模型 3/4，公开请求 2/2；实际公开 EVAS 执行累计 1 次；候选仍 C1 |
| 第 4 轮 seq 16–20 | Bash 调用 `vabench-submit` | 声明的提交通过 artifact gate；`done=true` | 模型 4/4；没有继续修改候选 |
| seq 21 | `submission_frozen` | 保存不可变提交 | freeze tree=C1 |
| seq 22 | `final_judgment_completed` | EVAS 隐藏终评 `behavior_failure / 0.0`，visibility=`trusted` | 只评分一次，judge tree=C1 |
| seq 23–24 | cleanup / episode completed | 无 cleanup incident；不再调用模型 | 最终状态保存，保留 0 分 |

实际轨迹共 25 个事件；另一个私有 capture 流共 23 个事件，记录请求/响应、
工具结果和 pause/resume。第二次 provider request 已包含缺文件反馈，第四次
已包含 waveform summary；全部 provider 请求/响应均早于 submission freeze。

本例有 3 次确认 pause、2 次确认 resume：前两次用于公开模拟的候选检查；
最后一次用于终止前冻结，不再恢复 generation，而是完成终评和清理。这不是
少配一次恢复；终态不再继续模型循环。

### 两个容易看错的数字

- **公开请求 2 次 ≠ EVAS 执行 2 次。** 第一次缺文件也占请求预算，但没有
  启动模拟器；回执确认的执行数为 1，计数完整标志为 true。这个计数也不包含
  最终 replay，不是所有 Bash EVAS 进程的全局计量。
- **模型额度剩 0 ≠ 这一轮动作必须丢弃。** 第四次合法响应仍可执行提交；
  不会仅因用完额度把正常提交误标成 `budget_exhausted`。

## 3. 五个组件在这四轮里分别做什么？

```text
Policy（请求模型并规范化动作）
  → Controller（授权、预算、状态转换）
    → Environment / tool（执行并返回 observation）
      → Policy 下一轮
             │ 提交完成
             ↓
       submission freeze → Final judge → immutable score evidence

Trajectory 在每个关键边界记事件；Final judge 没有返回 Policy 的路径。
```

| 组件 | 本案例中的责任 | 从哪里看代码 |
| --- | --- | --- |
| Policy / adapter | 保留 mini-swe 的消息格式，将一个响应转换为一个统一动作；它不拥有评分权限 | [NativeMiniSwePolicy](../../benchmark-vabench-release-v4/operations/calibration_pilot/run_native_mini_swe.py#L997)、[MiniSwePolicyBridge](../../runners/agent_harness/backends/mini_swe.py#L44) |
| Controller | 在执行前判定工具是否允许、参数是否合法、预算是否足够；处理候选变化和终态 | [EpisodeController.run](../../runners/agent_harness/controller.py#L180)、[tool registry](../../runners/agent_harness/tool_registry.py) |
| Environment / tool | Bash 复用原环境；固定公开工具负责 pause、候选检查、隔离模拟、恢复和 typed observation | [_RecordedEnvironment.step](../../benchmark-vabench-release-v4/operations/calibration_pilot/run_native_mini_swe.py#L252)、[PublicWaveformTool](../../runners/agent_harness/tools/public_waveform_tool.py)、[isolated executor](../../benchmark-vabench-release-v4/operations/calibration_pilot/public_waveform.py) |
| State / trajectory | 保留统一 action、observation、candidate identity；把授权、预算、执行、冻结与终评串起来 | [state.py](../../runners/agent_harness/state.py)、[JsonlTrajectoryRecorder](../../runners/agent_harness/trajectory.py#L48) |
| Final judge | 只接收已经冻结的 C1；核对 profile、树哈希与 sidecar，不通过普通工具返回模型 | [_ProductionFinalJudge.judge](../../benchmark-vabench-release-v4/operations/calibration_pilot/native_episode.py#L61)、[execute_bound_replay](../../benchmark-vabench-release-v4/operations/calibration_pilot/final_replay.py#L209) |

调用这些组件的总装入口是
[run_prepared_native_mini_swe](../../benchmark-vabench-release-v4/operations/calibration_pilot/run_native_mini_swe.py#L554)。
它选择 backend、构造环境/工具/profile，再调用统一 controller；不是把
mini-swe 的 `DefaultAgent` 循环再包一层重复执行。原 `DefaultAgent` 留在 legacy。

### 第一次请求为什么能够恢复？

[waveform_tool_descriptor](../../runners/agent_harness/tools/public_waveform_tool.py#L77)
只允许空 object 参数，声明 `public_validation` 预算、候选只读和非共享观察。
Controller 先授权、记账，随后 `PublicWaveformTool.step` 暂停生成容器并检查
候选。缺文件时返回可恢复 observation，`done=false`，不是 compiler 错误或终评分数。

第 3 轮文件完整后才调用隔离 executor。原始候选在 pause 期间不能被后台
Bash 子进程改写；执行用新的只读输入快照。恢复状态确认后，公开反馈才能进入
下一次请求。这里明确相信 host/coordinator/Docker；哈希不是数字签名。

### 公开波形为什么不能直接判“任务正确”？

这次公开回执实际声明：

```json
{
  "authority": "public_diagnostic",
  "task_correctness": "not_evaluated",
  "status": "succeeded",
  "returncode": 0,
  "usable_feedback": true
}
```

summary 可用，扫描 3501 行，返回 6 个信号，`incomplete_scan=false`。这些数
只说明公开模拟生成了可读取输出。候选只是占位逻辑，能运行并不保证满足任务。
最终隐藏检查返回 0 分时，harness 保留它，不根据此前公开成功改判。

这里没有为了讲解而展开 hidden checker 的规则、阈值或 gold 内容；也不从
`behavior_failure` 推导某个具体电路 bug。具体失败原因需要另一次有权限的诊断。

## 4. Trajectory 到底优化在哪里？

不是“以前没有日志，现在有日志”，而是将证据分成不同用途：

| 文件 / 信息层 | 保存什么 | 谁使用 |
| --- | --- | --- |
| `native-launcher/private-events.jsonl` | 请求/响应、工具参数/结果、输出捕获、pause/resume | 受控内部审查；本笔记不复制 raw 内容 |
| `native-episode/trajectory.jsonl` | action identity、参数/结果 hash、授权、预算、候选、终态 | 统一生命周期校验；含 trusted 事件，不等于整份可发回模型 |
| `native-launcher/reviewer-export.json` | 版本化安全投影与来源关联 | reviewer；不是原始轨迹的替代品 |
| `native-episode/scored-results/*.json` 与 `score-sidecars/*.json` | frozen candidate、trajectory tail、profile 和终评关联 | 只读评分/审计；不再启动第二次 judge |

seq 12 的 proposal 记录 C1，seq 15 的公开观察绑定 C1，seq 21 的 freeze
和 seq 22 的 judgment 仍绑定同一个 C1。与此同时，不同类型证据有各自的 hash：
候选树哈希、整个轨迹文件哈希、轨迹尾事件哈希不能混用。

[read_native_cell](../../benchmark-vabench-release-v4/operations/calibration_pilot/score_campaign.py#L461)
重建这些关联，并复核公开回执/预算与 private capture 的一致性。本轮运行它
成功，读取前后案例目录的 34 个文件字节哈希未变，没有重新生成或评分。
这证明该存量案例的证据链可读取，不是整个宿主环境的远程证明。

该案例启用了 waveform 扩展，因此**不送入普通 paired ledger**。AA063 的
安全 case 索引面向其支持的普通条件；本笔记是单案例审查，不绕过扩展混池 gate。

## 5. 和旧 mini-swe 路径相比，什么没变、什么变了？

这里比较代码/回归，不伪造一条“旧版波形专用工具”的运行轨迹。legacy 仍能
通过 Bash 调用公开 EVAS、查看 CSV，但没有这个 native 固定动作及独立回执接口。

历史归属另以 upstream `7b5616dc52195ec275ec6d21c71d7763613702cd` 核实：
上述 Docker / No-EVAS / 提交 gate / `DefaultAgent` 日志 / snapshot + trusted
replay 均已存在。该提交的 replay 文件允许删除后重建，不能把 fork 后来的
单次终评及 append-only sidecar 约束倒算为 upstream 功能；其非 Docker 模式
也不享有 Docker 挂载/网络隔离保证。

| 方面 | 旧路径已具备的基础 | native 的改变或差异 |
| --- | --- | --- |
| 隔离与权限 | Docker public-only mounts、network none、No-EVAS 镜像、提交检查 | 复用环境，增加统一 registry/capability 与状态后置条件检查；不是仅从提示词迁到代码 |
| agent loop | `DefaultAgent` 管理循环，runner 管理任务/终评 | Policy 只提案，通用 controller 管执行边界；Reasoning 可复用同一套协议 |
| 日志 | mini-swe trajectory、工具/EVAS telemetry | 再增加统一 hash-chain 生命周期和分层证据关联；Bash markers 仍属未认证诊断 |
| 合法单动作、补齐文件后提交 | 已能继续执行并提交 | 差分测试检查最终 candidate bytes/tree 相同；初始操作提示有明确差异 |
| 格式错误 | `FormatError` 重提示，受 wall time 约束 | 拒绝，不重提示；归为协议失败，而非 provider outage |
| 一次响应多个动作 | 顺序执行，成功提交会中断后续动作 | 整个 proposal 在执行前拒绝 |
| 响应迟于 deadline | 下一轮检查前本次动作可能已执行 | 不执行迟到动作；按既有规则处理当前完整提交 |
| 正确动作但 `finish_reason=length` | 记录 telemetry 后仍可执行 | 同样可执行，不把所有 output-cap 情况都当作协议错误 |

对应代码：旧 [run_mini_swe_episode](../../benchmark-vabench-release-v4/operations/calibration_pilot/mini_swe_vabench.py#L1625)
与 [run_mini_swe_agentic_cell](../../benchmark-vabench-release-v4/operations/calibration_pilot/run_campaign.py#L2462)；
新路径见第 3 节。行为矩阵的可执行依据是
[mini-swe differential tests](../../tests/test_agent_harness_mini_swe_differential.py)。
不能把未来分数差全归因于架构：提示词、格式恢复、多动作和 deadline 都可能影响结果。

## 7. 人工审查要回答的五个问题

1. 是否接受“缺文件是可恢复反馈，但也消耗一次固定工具请求”的语义？
2. 是否接受 native 的严格单动作/格式错误终止，且未来比较明确列出这些差异？
3. 本例公开诊断和终评已分开；正式实验是否还有别的资料/预算差异需要匹配？
4. 当前 hash/事件足以定位这个失败吗？若要解释电路原因，应另看哪些受控证据？
5. 下一轮是否先用同任务/模型研究 backend，再分别增加 Evolution、RAG 和波形，
   避免一次改变多个因素却无法归因？

本案例不证明模型变强、真实 RAG 有用、SFT/RL 可训练或 EVAS 与 Spectre 等价。
它也不证明所有故障路径都正确；本轮针对性回归补充了坏参数、预算拒绝、
receipt 篡改和清理异常等分支。没有发现需要在本轮修改 runtime 的新证据。
