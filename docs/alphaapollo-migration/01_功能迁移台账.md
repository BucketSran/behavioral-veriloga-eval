## 本轮新增记录

### 2026-08-30：Native campaign 证据过渡接入

- [AA-VAE-039](features/AA-VAE-039-native-campaign-evidence-bridge.md)：复用
  native launcher 的已评分 artifact，只读接入现有 score row；汇总增加显式
  scheduled-cell 分母门；smoke 可选择 legacy OneShot/No-EVAS + native Agentic。
- 代码：`score_campaign.py::{read_native_cell,summarize}`、三条件 smoke、
  native-campaign tests、evaluator-closure CI。完整映射、思想和命令见 feature note。
- 边界：mixed-backend connectivity，不是 all-native 或公平性能比较；不改 r53、
  EVAS 或旧默认路径。native No-EVAS authority absence/full CLI/retry 仍待后续。

### 2026-08-29：评测器角色与迁移笔记契约

- 新增/修改：`AGENTS.md`、`docs/alphaapollo-migration/`。
- 思想：EVAS 是当前快速且固定的开发/评测评分器；Spectre 是 EVAS 变化或显式外部
  审计时才触发的兼容门。AlphaApollo 的价值在 agent-environment 结构，不在复制其
  训练算法。
- 代码影响：本轮没有修改 runner、scorer 或 EVAS 实现，因此除已有能力外，不宣称
  新的 runtime 功能已经完成。
- 验证要求：检查 Markdown、仓库布局、链接、`git diff --check`；后续实现按本表逐项
  增加 targeted regression 与 clean-room smoke。

### 2026-08-29：r53 三条件 clean-room smoke

- 新增/修改：`scripts/run_v4_r53_clean_room_smoke.py`、
  `tests/test_v4_r53_clean_room_smoke.py`、`.github/workflows/evaluator-closure.yml`。
- 思想：学习 AlphaApollo 把一次求解视作 trajectory，而不是只看最终 response；
  vaEVAS 进一步把 trajectory 绑定到 final submission freeze 与 EVAS trusted replay
  sidecar，避免过程反馈和最终评分混淆。
- 代码影响：新增 deterministic public-contract smoke 入口，覆盖 `OneShot`、
  `Agent-No-EVAS`、`Agentic` 三个 matched arms；实际调用 `run_cell`，不读取
  hidden solution。freeze 改为不可覆盖，scorer 增加 sidecar-only 非回写模式，
  无 structured verdict 时 fail closed。
- 验证：新契约测试 `4 passed`；真实 Docker `v4-001` smoke 使用 EVAS 0.8.7
  得到 `judge_statuses={"behavior_failure": 3}`，这是中性不完整候选的预期评分；
  `Agent-No-EVAS` in-loop EVAS 调用为 0，`Agentic` 为 1，三条 trajectory
  hash chain 均通过。
- 边界：这是 harness/evaluator connectivity evidence，不是模型性能 baseline。

### 2026-08-29：通用 agent harness 边界原型

- 新增/修改：`runners/agent_harness/`、`tests/test_agent_harness_controller.py`、
  `features/AA-VAE-015-generic-harness-boundaries.md`。
- 思想：借鉴 AlphaApollo 的 reasoning/feedback trajectory 和 coding-agent 的
  environment-owned event loop，但把 public validation 与 final judge 做成不对称
  权限；final judgment 不能进入下一次模型调用。
- 代码影响：暂停 prototype 已完成逐模块 keep/rework disposition；新增版本化
  action/observation、candidate/payload hash binding、failure disposition、cleanup
  incident 与 retry lineage。production runner 暂未导入该 package。
- 边界：本功能只验证通用契约原型，不改变 r53、mini-swe、EVAS 0.8.7 或现有评分
  结果，也不实现尚未通过 design gate 的 vaEVAS 领域工具。

### 2026-08-30：Action/Observation canonical wire schema

- 新增/修改：`schemas/vaevas-action-v1.schema.json`、
  `schemas/vaevas-observation-v1.schema.json`、`runners/agent_harness/state.py`、
  `tests/test_agent_harness_protocol.py`、
  `features/AA-VAE-016-canonical-action-observation-schemas.md`。
- 思想：学习通用 agent harness 的内部事件归一化边界；provider 原生工具调用和本地
  模型 JSON 最终都必须落到同一种内部 Action/Observation 文档，backend 语法不能
  改写 trajectory 证据结构。
- 代码影响：可信 state serializer 生成 detached JSON 文档并计算 canonical hash；
