# vaEVAS 项目现状与功能缺口快照

- 记录日期：2026-08-30。
- 代码基线：fork `main`，`f1a2a06db7549a8ab46aebc664cddc9b4ef6710d`。
- 用途：供人工重新梳理项目，不自动启动下一项开发。

这是按上述提交核对的能力快照，不是相对某个“昨天”提交的逐行 diff。
九组缺口是工作分类，不是九个 bug，也不是九项全都需要从零实现。
后续比较应保留这个基线，另行记录已关闭、仍开放或明确暂缓的事项。

## 1. 项目现在是什么

主线保持：**VABench v4/r53 + AI-native generation harness + public EVAS
feedback + submission freeze + strict EVAS trusted replay + 可追溯结果。**

- r53 固定为 400 families / 1,200 tasks；EVAS 固定为 `evas-sim==0.8.7`。
- 原有 mini-swe 仍是默认后端和比较基线，旧批量实验入口保留。
- 新 native mini-swe 是独立 opt-in 路径，不是 AlphaApollo reasoning 后端。
- AlphaApollo Reasoning 和多模型 Evolution 是后续目标，目前没有生产运行后端。
- 只向 BucketSran fork 写入；不改 upstream、封存 r53、EVAS 或旧工作树。

当前的准确判断是：**基础评测链路已通，新 native 路径有界接通；通用多后端、
多模型演化和完整实验结果生成尚未闭环。**

## 3. 九组主线缺口

### GAP-01：native 全条件、全题型支持（部分接通）

- 现状：native launcher 只支持 G2 Agentic 的 DUT/bugfix；三条件 smoke 中
  OneShot 和 No-EVAS 仍走 legacy。Testbench 的旧公共/评分契约已经存在。
- 缺口：native OneShot/No-EVAS 的无公开验证器契约、对应隔离环境、Testbench
  的 reference-DUT-only 公开验证适配，以及各组合的 clean-room 验证。
- 完成标志：声明的 native 条件/题型真正可运行；No-EVAS 的禁用由 runtime
  强制执行，OneShot 不被改成多轮 Bash agent，隐藏故障和终评不进入公开反馈。

### GAP-02：完整批量 campaign 接入（部分接通）

- 现状：旧 campaign build/run/summary 已有；native 单任务入口与只读评分桥已有。
- 缺口：把 native 接入批量调度、冻结 profile 分发、终态记录及统一汇总。
  默认 scorer 仍按已有 `campaign_result.json` 枚举结果，未给 `summarize` 传入
  `scheduled_cells`，也不会自动读取 native runtime。
- 完成标志：每个计划 cell 都有且只有一个明确计入的终态；缺行、重复、身份错配
  会阻止相应报表，系统失败不被丢弃或变成模型零分。

### GAP-03：重试、恢复和候选处置（部分实现）

- 现状：已有 native reservation/no-reentry、不可变 freeze、失败与 incident 记录。
- 缺口：基础设施失败的新 attempt 重试协调、崩溃后的证据处置、父子 lineage、
  计入终态的选择规则，以及错误候选修改后的事务回滚或明确丢弃策略。
- 完成标志：重试使用新环境和新 attempt，不覆盖旧证据、不按分数重试；cleanup
  失败不覆盖主要结果。provider 内部 transport retry 不冒充 cell retry。

### GAP-04：跨后端计量与资源证据（已有基础）

- 现状：已有 wall-time、资源限制、模型 token telemetry，以及工具/公开验证预算。
- 缺口：跨后端统一 request/response、调用数、token、耗时、资源与 evaluator
  使用证据；未来 evolution 还需跨分支总成本核对，native provider 失败分类需细化。
- 完成标志：缺失的 provider 元数据明确标记，成本可追溯且可比较。
  r53 现有 1,800 秒 wall-time 主预算不变；不偷偷把累计 token 改成新的终止条件。

### GAP-05：完整 trajectory 审计与导出（部分实现）

- 现状：原生事件链、已解码模型交互、受限 Bash 输出与评分 artifact 已有。
- 缺口：transport retry/流式传输证据、完整工具日志的受控私有归档、版本化
  脱敏 normalizer、公开导出与原始记录的哈希索引及完整事件关联。
- 完成标志：导出保留顺序、身份、失败和 join keys，可追溯到私有证据；凭据、
  hidden checker 与终评分数不会进入模型下一轮或共享 memory。

### GAP-06：AlphaApollo Reasoning 后端（运行后端未实现）

- 现状：可复用 controller、proposal normalizer、registry、模型/Bash adapter
  和评分接口；现有 native mini-swe 不等同于 AlphaApollo reasoning。
- 缺口：单轨迹 reasoning policy/backend、本地/API 模型适配与上述接口的接入。
- 完成标志：在匹配任务、模型、公开能力、预算和最终评分的条件下完成契约测试、
  clean-room smoke 与 mini-swe 差分；有意协议差异必须显式列出。

### GAP-07：AlphaApollo 多模型 Evolution（契约已有，运行编排未实现）

- 现状：manifest、memory snapshot、candidate lineage 与确定性选优函数可执行，
  但生产 launcher/controller 尚未消费成真正的 evolution 流程。
- 缺口：不同模型并行生成、独立候选目录、轮次同步、公开反馈快照、共享 memory、
  跨轮改进、失败分支处置、最终选优和一次终评。
- 完成标志：同轮各分支只看到相同的已冻结反馈；完成先后不改变信息集合或选优；
  候选来源和影响关系可追溯，终评不能触发下一轮。

### GAP-08：结果到图表/结论的完整生成（已有汇总，未全链闭环）

- 现状：已有评分汇总、失败分类、sidecar、native 行投影和局部严格分母门。
- 缺口：全 campaign 的 record-level ledger 到表格、图、claim index 的关联；
  配对比较、成本、不确定性、deadline 分析及各报告切片的分母校验。
- 完成标志：每个结果数字都能定位到冻结配置、计入的 attempt、提交、评分与分析
  版本；不混报单次结果、best-of-k 和多分支 evolution。

### GAP-09：覆盖矩阵与真实模型实验（现有验证不足以替代）

- 现状：确定性 provider、协议差分、真实 Docker/EVAS 与 CI 已有通过证据。
- 缺口：全声明条件/题型的验证矩阵、新架构真实模型小规模 pilot、Reasoning 与
  Evolution 的对照实验，以及本机遗留 legacy timeout 用例问题的诊断和闭环。
- 完成标志：运行可靠性证据与模型质量证据分开；仅对实际匹配的能力、预算、
  模型和评测范围作比较，不把本轮 smoke 当成论文 baseline 复现。

- 领域工具、波形助手、RAG、结构化编辑：保持占位，具体工具须另行讨论。

- DUT/bugfix 的现有 r53 是共享刺激、held-out checker，不是完全独立的隐藏刺激集；
  真正不相交的刺激协议需要后继 revision，不能在本轮暗改封存内容。
- 全量抹平旧/新 mini-swe 协议差异：不是默认目标，保留已声明的有意差异。

另有维护债而非新功能：早期台账“下一缺口”有些已被后续切片解决；应按最新实现
核对，不能累加历史文字。native reader 对私有目录布局的依赖是已记录 WATCH，
不是现在就新增抽象层的理由。CI Node-action 弃用警告也单独归为维护项。
