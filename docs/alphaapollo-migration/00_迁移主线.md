# AlphaApollo → vaEVAS 迁移主线

## 一句话定位

AlphaApollo 主要研究如何让 agent 在环境中形成多轮 trajectory，并通过训练或
test-time evolution 改进解题；vaEVAS 主要研究如何让模型在 Verilog-A 任务中
生成、执行、观察、修订，并以可复现、无泄漏的方式完成评测。

因此我们的迁移原则是：

> 学习 AlphaApollo 的 agent-environment 软件结构和可观察交互，不把它的
> SFT/RL 训练目标、数学任务假设或 verifier 投票直接搬进 benchmark 评分。

## 当前 vaEVAS 主链

```text
frozen VABench v4/r53 task + campaign manifest
    ↓
fresh isolated runtime / one evaluation cell
    ↓
model produces a structured action or submission
    ↓
harness parses and validates the action
    ↓
tool or public EVAS executes against the current candidate tree
    ↓
observation returns to the same trajectory only
    ↓
bounded propose → execute → observe → update loop
    ↓
content-addressed final submission freeze
    ↓
strict EVAS trusted replay and immutable score sidecar
    ↓
record-level result ledger → aggregate → claim-to-evidence index
```

Spectre 不在普通开发循环中。只有 EVAS 自身发生代码、编译器、模拟语义、ABI、
打包或版本变更，或者某个明确命名的外部/最终协议要求时，才启用 Spectre parity
audit。EVAS 结果必须始终标注 `judge_engine=evas`，不能改名为 Spectre 结果。

## 可迁移的思想

| AlphaApollo 思想 | 在 vaEVAS 中的适配 | 为什么有价值 |
| --- | --- | --- |
| 一个样本是完整 trajectory，不是单次 response | 评测单元绑定 task、attempt、model turn、tool/EVAS observation、submission 和 score | 防止只保存最终答案，无法解释中间失败或泄漏 |
| 由 environment/controller 拥有状态与循环 | harness 管理 workspace、budget、tool execution、done 与 retry；模型只产生动作 | 将可重复性和安全边界放在模型外部 |
| 每条并行 trajectory 有独立状态 | 每个 cell 使用独立 sandbox、candidate tree、memory、attempt ID 和证据流 | 避免跨任务、跨模型或跨条件污染 |
| action validation、tool parsing、execution、termination 分层 | 结构化解析、参数归一化、工具执行、提交 gate 和 terminal outcome 分开记录 | 协议违规不能被误当成工具成功或任务正确 |
| short-term memory 是外部程序状态 | 只允许同一 episode 内的公开 action/observation 进入下一轮 prompt | 便于审计 memory scope，防止隐藏信息或跨任务泄漏 |
| propose → verify → update 的 test-time evolution | 仅用于 development 或显式冻结预算的 agentic condition | 提升搜索效率，同时维持公平比较 |
| feedback 与 correctness 分离 | 公共 EVAS 反馈是过程事件；最终 strict EVAS replay 是评分事件 | 避免把“调用过 EVAS”误写成“任务已正确” |

## 不直接迁移的内容

| AlphaApollo 内容 | vaEVAS 决策 | 原因 |
| --- | --- | --- |
| GRPO、PPO、turn-level SFT | `暂不迁移` | 当前主线是 benchmark 与 harness closure，不是训练新模型 |
| 跨题或跨评测单元的 SolutionMemory | `禁止用于正式 cell` | 会破坏 clean-room、独立同分布和泄漏边界 |
| 多 verifier 投票作为真值 | `不作为评分器` | Verilog-A 任务有可执行 evaluator 与 checker |
| 任意模型生成代码的宽松本地执行 | `不迁移` | vaEVAS 需要受限工具 schema、sandbox、超时和路径约束 |
| 默认 best-of-k / 多分支搜索 | `仅作为命名实验条件` | 预算和估计量不同，不能与单次生成混报 |

## 来源与推断纪律

本主线综合了 AlphaApollo [公开论文](https://arxiv.org/abs/2510.06261)、
[公开代码仓库](https://github.com/tmlr-group/AlphaApollo)以及用户授权的历史
Codex 学习对话。对话中最重要的工程结论是：采样所有权要放在 environment
trajectory 层；memory 是显式程序状态；controller 是循环和状态机；合法性、
执行与终止是不同维度。

这些结论是迁移启发，不是 vaEVAS 已实现的证据。是否完成只能由本仓库的代码、
测试、smoke 与冻结结果证明。
