## Acceptance / KPI

1. Evolution remains NoEVAS during branch generation. The coordinator's optional
   waveform validation consumes the existing public validation allowance once
   per candidate. Bind bounded public observations to sealed candidate bytes,
   validation profile and receipt; expose them only across that run's next-round
   barrier. No raw waveform, final score, hidden checker or cross-task memory.
   Preserve deterministic candidate selection and one selected final replay.
2. Keep synthetic corpus v1 compatible. An explicit reviewed local corpus mode
   pins exact document bytes, upstream origin/revision and recorded rights and
   contamination review. Local context permission is not external-provider
   permission. No implicit network retrieval, whole-repository ingestion or
   claim that an operator assertion proves licensing/absence of contamination.
3. A separate combined launch freezes backend, corpus, waveform policy, rounds,
   branch fanout, public/model/tool budgets, provider and source identity before
   calls. Reuse a single shared spending guard. Preparation and read-only
   reporting do not load keys or spend; live execution retains explicit exact
   manifest/cap assertion, no silent retries or budget resets.
4. Evidence distinguishes enabled features from observed retrieval, waveform
   execution and next-round consumption. Preserve incomplete/unstarted outcomes
   and aggregate all branch costs. Reports only read existing bound evidence;
   they cannot call a model, refreeze or run another judge.
5. Vertical RED/GREEN, compatibility and adversarial tests; real Docker/EVAS
   with synthetic model replies, independent review and focused fork commits.
   This proves integration, not real-model quality or individual tool benefit.
